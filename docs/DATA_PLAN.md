# Data Plan

## Phase 1: Local Seed Data

Keep data in TypeScript or JSON while shaping the dashboard:

- Daily signal scores.
- Metric cards.
- Nudges.
- Source freshness.

This keeps the first build focused on user experience.

## Phase 2: Local Imports

Add file imports before direct integrations:

- Apple Health export XML or CSV generated by an iOS Shortcut.
- Scale data through Apple Health if the scale already syncs there.
- MyFitnessPal CSV or manual weekly macro entry.

Store normalized records locally.

### Current one-time import

`scripts/build_health_data.py` produces `src/data/health-data.json` from the current raw export. It uses streaming XML parsing for the large Apple Health file, includes daily metrics and workouts, and stores GPX route metadata without embedding track points. The MyFitnessPal PDF is parsed with `pypdf` into daily nutrition totals; this is a one-time bridge until CSV exports are available.

The dashboard reads the latest seven imported days from this JSON fixture rather than the original seed values.

The importer trims all dated records to the three months ending on the latest imported date before writing the fixture.

Sleep segments from Apple Watch are grouped by overnight window: records beginning from 8:00 PM through 11:00 AM belong to the same sleep night; records beginning after 11:00 AM through 7:59 PM are excluded from overnight sleep totals.

Step totals prefer Apple Watch records when available and fall back to iPhone records only on days without Watch samples. This avoids double-counting overlapping device samples.

See `MANUAL_DATA_EXPORT.md` for the first manual collection workflow.

Suggested normalized tables:

- `daily_metrics`: date, sleep_minutes, steps, resting_hr, hrv, active_calories, weight_lb.
- `workouts`: date, type, duration_minutes, calories, effort.
- `nutrition_days`: date, calories, protein_g, carbs_g, fat_g, fiber_g.
- `nudges`: date, category, title, body, status.

## Phase 3: App Logic

Move from static data to rule-based calculations:

- Seven-day and 28-day trends.
- Goal progress.
- Readiness and sub-score calculations.
- Nudge generation from missed targets or improving trends.

## Phase 4: Integrations

Only add direct integrations after imports prove useful:

- HealthKit via iOS if direct Apple Health access becomes essential.
- MyFitnessPal automation only if export/manual entry is too annoying.
- Optional cloud sync after local privacy expectations are clear.

## Data Safety

Treat all records as private health data:

- Keep local storage unshared by default.
- Avoid committing real exports.
- Add `.gitignore` rules for raw imports before using personal data.
